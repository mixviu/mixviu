# Quoin P2 specimen

Lab only, based on P0. Never merge this branch. Production work follows an
independent whole-specimen survey. No desktop installation or VT changes.

## Shape

`publish_patch(ctx, "model.clock.time", value)` calls `scenes.patch`. The
loader checks the same behaviour generation fence as `scenes.model`, updates
its cached model and forwards the path. Complete publications recursively
diff maps; lists and scalars replace as a unit. Dotted/empty keys and explicit
nil values replace their parent because the existing path grammar cannot
address those faithfully. A single leaf uses the existing wire envelope;
multiple leaves use `{scene,generation,patches:[{path,value}]}` on
`shell.scene.patch`. The host commits only after every patch is accepted.
Intermediate layout conflicts still reject a batch; the derived implementation
should apply data first and evaluate the union of dependencies once.

`ResolvedScene.sources` is separate from `model`. The expression adapter
supplies a pure `src` global and records `src.*` dependencies alongside
`model.*`. Model replacement cannot erase sources. Row template evaluation
receives the same source snapshot. Source patches retain the loader ownership
check at host ingress, but do not require a behaviour generation: a source-only
scene has no behaviour.

The Mix loader owns one source coordinator for its host. Declare strict data:

```text
sources: {clock: {every: "1s"}, comp: [outputs, workspaces, windows], audio: true, net: true}
```

The lab supports only `clock.every: "1s"`. Clock fields are `unix`, `time`
(local `%H:%M`) and `date` (local `%a %d %b`). Audio/net expose the native
`audio_state`/`net_state` maps unchanged. They start one native watch each
when first requested. A source is shared across declaring scenes; each scene
gets only its selected compositor collections. Bindings remain free of I/O.
The panel declares clock and comp and reads its two clock labels from src.
Existing behaviour workspaces/tasks remain model-driven for comparison.
The panel behaviour's existing clock task also remains (it supplies tooltip
and model state); the specimen does not claim an end-to-end reduction in
timer/RPC traffic. Metadata is re-read during each distribution pass, another
cost outside the renderer micro-measurement.

The host subscribes before `comp.props.watch` and `comp.props.get {}`. Watch
returns a watermark, **not a property snapshot**. Outputs/workspaces refresh
on props notices and reconnect, with bounded calls. The one-second settings
and panel-report timer remains; compositor snapshots no longer run on it
after successful connection setup. The loader's source coordinator is a
second consumer of the existing compositor topic, not a second transport.
The derived implementation should share that host subscription too.

## Discoveries and limits

- Sending several leaf RPCs allowed a rejected later leaf to leave earlier
  changes committed. The batch prototype preserves last-good atomically.
- Resolving a scene before its source snapshot can leave required ports
  unset: nested access through an absent source fails evaluation. The
  50-property test therefore seeds a snapshot before measuring mutations.
  Production needs declared defaults/availability and snapshot-at-load.
- Source metadata is checked during distribution, rather than the loader's
  acceptance transaction. Failed providers, gaps and restart races need
  dedicated integration fixtures; source cache invalidation currently reads
  a full compositor snapshot per notice and then diffs it.
- Audio/net watches remain allocated until loader shutdown, even when their
  last scene disappears. Provider closure has no bounded retry yet. Source
  delivery can partially succeed across scenes. None of this is production
  lifecycle policy.
- The loader runs native audio/net reads in its synchronous writer path.
  A derived implementation should collect snapshots asynchronously and commit
  under the writer, preserving generation checks.
- No live hotplug or real presentation test was performed: the task forbids
  touching the evaluation desktop and VTs. CPU panel measurement uses the
  actual shipped document and renderer, with empty authored tasks/tray,
  headlessly on the build service. It excludes GPU, broker and presentation.
  This is not a captured live-workload oracle.

## Conformance and measurement

The scene test has 50 text bindings, seeds their source snapshot, mutates
`src.clock.v17`, and asserts exactly `n17.text` re-evaluates and changes.
Root publication evaluates 50 properties; unrelated model publication
evaluates none and retains sources. The host tests batch refusal/commit.
Mix tests cover path diff/apply, generation fencing and literal nil/dot cases.

The panel CPU test runs 10 warmups and 100 retained samples for the old
whole-model path and the new single source path at 1920 x 52. It reports
patch median/p95, template preparation plus CPU frame median/p95 and actual
re-evaluation counts. Results and build receipts are in `last.md`.

## Proposed derived PRs and P3 hand-off

1. Path publication, model diff and a bounded transactional path batch, with
   one dirty-set union and one re-evaluation pass. Preserve the model fence.
2. Declared source API, shared host-owned subscriptions and snapshots at load,
   availability/defaults, provider lifecycle and reconnection/gap tests;
   migrate panel bindings and remove compositor polling. Keep services in Mix.

P3 should consume `src.comp.outputs`, `src.comp.workspaces` and
`src.comp.windows` as the native keyed collections, retaining stable compositor
keys. Do not manufacture order or identity from enumeration indices. `repeat`
needs a bounded ordered projection with an explicit key and declared ordering;
per-output scenes need an initial coherent snapshot plus add/remove changes,
and an independent `instance.output` root. Define sequence/watermark, stale
state, deletion and availability before deriving P3. Repeat's dependency on
a collection must intersect descendant source paths. Source ownership is once
per host; per-output instances must not start new watches or behaviours.

Overlap with P1: `scripts/scenes.mix` handlers and publication wrapper,
`scripts/lib/scenes.mix` model/reload branches, `runtime.rs` worker loop,
and `store.rs` patch receipts. Overlap with P3: binding root/dependency
policy, `ResolvedScene.sources`, template context, source metadata and panel
document. Reconcile designs through the survey; do not merge lab branches.
